## Root causes / remaining gap 1
- Test 1026 demonstrates a Tree/token evaluator mixed signed/unsigned comparison divergence (`int -3 < unsigned int 4` must be false).
- Test 1027 demonstrates incorrect signed/unsigned bit-field promotions in both Tree and Linear for a 5-bit unsigned field whose range fits in `int`; C integer promotions promote that field to `int`.
- Canonical expression-result type inference computed exactly once in lowering and consumed by both shared evaluator and Linear is not implemented for all forms (notably calls/returns, member/bit-field, indexed/dereferenced access, assignment and compound assignment).
- Enum conversion coverage is only partial; exhaustive operator × type generation is not complete.
- LP64 was built/tested on this host. LLP64/MSVC behavior is expressed via compiler type widths but not verified with MSVC.
- Therefore this is an honest partial delta, not full closure of gap 1.
