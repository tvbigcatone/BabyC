# BabyC — attempt16: va_arg pointer expressions and single evaluation

## Scope

Cumulative delta over attempt15. The caller-side typed ABI payload item (gap 2(b)) remains deferred as requested. This turn targets pointer-valued `va_arg` expressions and duplicate evaluation while packing native-call arguments.

## Changes included

- `src/ir_exec.c`: `IrExprYieldsPointer()` recognizes pointer-typed `IrExVaArg`, pointer-valued index/member results, and pointer-valued dereferences using expression type metadata. `IrExprIsFP()` no longer resolves a member expression merely to classify it as floating-point; resolving a member can execute its call/`va_arg` base.
- `src/ir_compile.c`: `va_arg` results flow into postfix parsing; the IR parser accepts pointer dereference, indexing, and `->` based on a `va_arg` expression.
- `src/ir_mem.c`: pointer element stride and address resolution use the requested `va_arg` pointee type; typed `->` member resolution uses the requested struct/union type. This includes `va_arg(ap, T *)[i]`, `*(va_arg(ap, T *) + i)`, and `va_arg(ap, struct T *)->member`.
- `src/ir_lin_emit.c`: Linear pointer classification/stride knows pointer-valued `va_arg` expressions.
- `src/ir_eval.c`: native-call argument packing was changed to avoid an address-resolution probe followed by a second full expression evaluation. The intent is single evaluation for member/index/dereference arguments with side effects.
- Added tests 1064 (pointer-valued `va_arg` forms) and 1065 (single-evaluation side effects in native arguments), with expected outputs generated by GCC `-O0`.
