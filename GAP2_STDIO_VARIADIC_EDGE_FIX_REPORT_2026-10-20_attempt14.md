# BabyC gap 2 — stdio variadic edge fixes (attempt14)

Baseline/delta: cumulative over the fixed `loop_promotion` baseline and attempt13.

## Implemented in this delta

- `src/cstdlib/stdio.c`: `*` width/precision now consumes an argument for cursor-backed `va_list` as well as ordinary `Param[]`; `%n` uses the same argument accessor instead of indexing `Param[]` directly.
- Negative dynamic width is translated to left adjustment plus absolute width (bounded to the existing safety cap); negative dynamic precision removes the precision marker and behaves as omitted.
- `sscanf`/`fscanf`/`scanf` and their `v*` routes now retain destination Values and mark successful variadic writes as initialized. Added `IrFrameMarkAddressInitialized()` for address-taken scalar locals in active IR frames; this fixes Linear's false uninitialized diagnostic for the tested scalar destinations.
- Added tests 1059 and 1060 with `.expect` output generated by GCC `-O0`. They cover `vsnprintf` with `*`/`.*`, negative width/precision with direct `printf`, `%n` through a variadic `vsnprintf` wrapper, `vprintf`, and `sscanf`/`vsscanf` writes into previously uninitialized int/double/char-array/long-long objects.

## Verification actually performed

- `make clean && make -j8`: success, 0 warnings, 0 errors.
- Tests 1059 and 1060: both pass in all six combinations (Tree ACCEL 0/1, Linear STRICT ACCEL 0/1, Linear non-STRICT ACCEL 0/1); output matches their GCC `-O0` `.expect` files.
- Tree full suite: the official dual runner's A-IR and IR-shadow0 passes were 1051/1051; its NO_IR pass had three existing failures (`380_analyze_mode`, `553_ir_struct_array_brace`, `580_stack_host_and_virtual`). The attempted full Linear matrix run did not finish within the allotted execution window, so no full-matrix claim is made.
- Canonical gate counters and `tree_body` were not collected for this attempt. A/B benchmark runs (7 alternating runs on four benchmarks at ACCEL 0/1) were not performed. MSVC/LLP64 was not tested.

## Still open

- Gap 2(b) remains open: the caller-side variadic payload is not yet consistently bound to the static promoted type in every IR/Linear call site; typed `Payload.D/U/P` propagation and `StdargVaArgBits()` type-directed decoding are not complete.
- Initialization tracking for scanf-family variadic writes has been fixed for scalar local addresses and exercised for the requested test shapes; broader nested/member/array subobject alias cases still need dedicated tests.
- The complete six-configuration suite, canonical gate, no-fallback counters, benchmark A/B, and MSVC/LLP64 validation remain to be run.
